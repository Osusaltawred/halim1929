# أرشيف عبد الحليم حافظ الرقمي

موقع عربي (RTL) للجوال أولًا، يعمل كمكتبة وأرشيف: أغانٍ وتسجيلات، حفلات، مقابلات، جلسات، أفلام، صور، أشخاص، خط زمني، ومصادر مع درجة التأكد. مع لوحة إدارة كاملة.

**لا يحتوي المشروع على أي أغنية أو صورة محمية بحقوق النشر.** كل الوسائط تضيفها أنت بنفسك.

## التشغيل السريع

يحتاج **Node.js 22.13 أو أحدث** فقط. لا توجد حزم للتثبيت (لا `npm install`) ولا خطوة بناء.

```bash
node server.js          # أو: npm start
```

افتح `http://localhost:3000`. لوحة الإدارة على `/admin`.

في أول تشغيل تُطبع كلمة مرور الإدارة **مرة واحدة** في الشاشة. غيّرها من الإعدادات، أو حدّد كلمتك من البداية:

```bash
ADMIN_PASSWORD="كلمتك" node server.js
```

للاختبار الآلي: `npm test`.

## الفكرة الأهم: فصل الكود عن بياناتك

```
halim-archive/
├── server.js, lib/, public/, seed/     ← الكود (يُستبدل عند كل تحديث)
└── data/                               ← بياناتك (لا يُمسّ عند التحديث)
    ├── archive.db                      ← قاعدة البيانات
    ├── media/audio/                    ← ملفات MP3
    ├── media/images/                   ← الصور
    ├── media/images/thumbs/            ← مصغّرات الصور (تُنشأ تلقائيًا عند الرفع)
    ├── media/video/
    ├── backups/                        ← نسخ القاعدة الاحتياطية
    ├── admin.json                      ← كلمة مرور الإدارة (مشفّرة)
    └── secret.key                      ← مفتاح توقيع الجلسات
```

مكان مجلد `data` يحدده المتغير `DATA_DIR`. على أي استضافة اجعله يشير إلى **قرص دائم**. طالما بقي هذا المجلد سليمًا فلن تضيع الأغاني ولا الصور ولا القاعدة ولا روابط MP3، مهما أعدت البناء أو النشر.

البيانات الأولية (`seed/seed.json`) تُحمَّل **مرة واحدة فقط** عند أول تشغيل على قاعدة فارغة، ولا تعود أبدًا.

## الأسئلة الاثنا عشر

### 1) أين أضع ملفات MP3؟
في `data/media/audio/`. بديلان أسهل: ارفعها من لوحة الإدارة (نموذج التسجيل أو شاشة «الملفات»)، أو انسخها للمجلد مباشرة (مثلًا بـ `rsync` أو `scp` لآلاف الملفات). ما ينسخ يدويًا يظهر في **الإدارة ← الملفات** كـ«غير مرتبط».

### 2) أين أضع الصور؟
في `data/media/images/`. الأفضل رفعها من الإدارة لأنها تُصغَّر في المتصفح وتُنشأ لها مصغّرات تسرّع الشبكات على الجوال. الصور المنسوخة يدويًا تعمل أيضًا.

### 3) كيف أضيف أغنية؟
**الإدارة ← «+ أغنية»** ثم:
اكتب اسم الأغنية (تختار أغنية موجودة، أو تنشئ جديدة) ← التصنيف ← الملحن والشاعر (يُنشأ الشخص تلقائيًا إن لم يكن موجودًا) ← نوع التسجيل ← التاريخ ← ارفع MP3 ← اربطها بحفلة أو فيلم إن وُجد ← المصدر ← **حفظ**.
- «**حفظ وإضافة أخرى**» يحتفظ بالحفلة والتاريخ والنوع لتسريع إدخال أغاني حفلة كاملة.
- نسخة ثانية من نفس الأغنية: من **الأغاني** اضغط أيقونة النغمة، أو اختر نفس الاسم في النموذج. ستظهر كل النسخ للمقارنة في صفحة الأغنية.

### 4) كيف أضيف حفلة؟
**الإدارة ← الحفلات ← إضافة**: الاسم، التاريخ، المكان، المدينة، الدولة، المناسبة، الصورة، روابط الفيديو (يوتيوب/فيميو)، تسجيلات مرفقة، مصادر. أغاني الحفلة تُربط بها من نموذج كل تسجيل (حقل «الحفلة»)، فتظهر قائمة الأغاني في صفحة الحفلة تلقائيًا.

### 5) كيف أضيف مقابلة؟
**الإدارة ← المقابلات ← إضافة**: العنوان، التاريخ، البرنامج أو الجهة، المذيع، المدة، الوصف. التسجيل الصوتي أو رابط الفيديو في حقل «الوسائط».

### 6) كيف أضيف جلسة؟
**الإدارة ← الجلسات ← إضافة**: التاريخ، المكان، الأشخاص الموجودون، الملاحظات، ثم اربط الأغاني بها من نموذج التسجيل (حقل «الجلسة»).

### 7) كيف أضيف صورة؟
**الإدارة ← الصور ← إضافة** لصورة واحدة بكل بياناتها (التصنيف، اللون، التاريخ، المكان، الأشخاص، المصدر). لعشرات الصور: **الإدارة ← الملفات**، اسحب الصور، ثم «إنشاء سجلات»، وعدّل التفاصيل لاحقًا.

### 8) كيف أضيف بيانات كثيرة دفعة واحدة؟
**الإدارة ← استيراد**:
1. اختر النوع (أغاني/تسجيلات، حفلات، مقابلات، ...).
2. نزّل **قالب CSV** وافتحه في Excel أو Google Sheets واملأه (رؤوس الأعمدة عربية).
3. ارفع الملف واضغط **تجربة بدون حفظ** لترى الأخطاء بالسطر، ثم **استيراد**.

- عدة ملحنين في خانة واحدة: افصل بـ `؛`
- «ملف الصوت» = اسم الملف الموجود في `data/media/audio`.
- الصفوف المكررة تُتجاوز، فإعادة الاستيراد آمنة.
- يدعم JSON أيضًا، ويمكن ملف واحد بمفاتيح متعددة: `{"people":[...],"concerts":[...],"recordings":[...]}`.

للملفات الصوتية بالآلاف: انسخها لمجلد الصوت، ثم **الإدارة ← الملفات ← إنشاء سجلات لكل الملفات غير المرتبطة**، أو ضع أسماءها في عمود «ملف الصوت» بملف CSV مع البيانات الكاملة.

### 9) كيف أحفظ قاعدة البيانات؟
- **من الإدارة ← الإعدادات**: «تنزيل قاعدة البيانات (.db)» و«تصدير JSON».
- تُنسخ تلقائيًا نسخة داخل `data/backups/` عند كل تنزيل (آخر 10).
- **نسخة كاملة** (الأفضل): انسخ مجلد `data/` كله. يكفي: `cp -r data data-backup-$(date +%F)` أو `rsync -a data/ /مكان/آمن/`.
- خذ نسخة قبل أي تحديث كبير، وبعد كل جلسة إدخال طويلة.

### 10) كيف أعيد Build للموقع بعد إضافة الملفات؟
**لا حاجة لأي Build.** الملفات والبيانات تظهر فورًا بعد رفعها أو إضافتها، فلا يوجد تجميع أو تحويل. الـ Build يحدث فقط إذا استخدمت Docker (السؤال التالي)، وهو يبني **الكود** فقط، لا بياناتك.

### 11) كيف أعيد Deploy للموقع؟
**بـ Docker** (الأبسط):
```bash
export ADMIN_PASSWORD="كلمتك"
docker compose up -d --build      # يبني الكود ويشغّله، وبياناتك في ./data
```
لتحديث الكود لاحقًا: استبدل ملفات الكود (`server.js`, `lib/`, `public/`, `seed/`, `Dockerfile`) واترك `data/` كما هو، ثم أعد الأمر نفسه.

**بدون Docker** على خادم/VPS: انسخ الكود، ثم `DATA_DIR=/var/halim-data ADMIN_PASSWORD=... node server.js` (ويفضل تشغيله عبر `systemd` أو `pm2`، وخلف Nginx/Caddy لـ HTTPS).

**على منصات الاستضافة** (Render, Railway, Fly.io وأشباهها): أنشئ خدمة Node (أو من `Dockerfile`)، وأضف **Persistent Disk/Volume** مربوطًا بالمسار `/data`، واضبط المتغيرين `DATA_DIR=/data` و`ADMIN_PASSWORD`.
> بدون قرص دائم تُمسح البيانات عند كل نشر. هذا أهم إعداد في المشروع كله.

لرفع ملفات كثيرة إلى خادم بعيد: `rsync -avz data/media/ user@server:/data/media/`

### 12) كيف أتأكد أن الملفات والبيانات لن تضيع بعد إعادة النشر؟
قائمة تحقق قبل أول نشر حقيقي:
1. `DATA_DIR` يشير إلى **قرص دائم** (وليس داخل مجلد الكود ولا داخل حاوية بلا Volume).
2. أضف أغنية تجريبية وارفع لها MP3.
3. أعد النشر (Build/Deploy كاملًا).
4. ادخل وتأكد أن الأغنية والصوت والصور ما زالت هناك.
5. الإدارة ← نظرة عامة تعرض «أين تُحفظ بياناتك؟»، وتأكد أن المسار هو القرص الدائم.

ولأن الكود لا يعدّل `data/` إلا عبر لوحة الإدارة، وقاعدة البيانات لها نظام ترحيل (`lib/db.js`) يضيف الأعمدة الجديدة دون حذف بيانات قديمة، فالتحديثات المستقبلية آمنة.

## صدق المعلومات التاريخية

- لا تُخترع تواريخ. حقل ناقص يظهر «**بيانات تحتاج إلى إدخال**»، وتاريخ مجهول يظهر «**التاريخ غير مؤكد**».
- إن لم تعرف التاريخ بالضبط، استعمل «تقدير: من سنة / إلى سنة». يظهر في الموقع: «يرجح أنه بين 1965 و1967 (تقدير وليس حقيقة مؤكدة)».
- **درجة التأكد**: مؤكد، مرجح، غير مؤكد، غير معروف. تُسجَّل لتاريخ كل تسجيل ولكل مصدر على حدة.
- **المصادر**: يمكن ربط أكثر من مصدر بأي أغنية أو تسجيل أو حفلة أو غيرها، ولكل رابط مصدر: أي معلومة يدعمها (تاريخ، مكان، ملحن...)، ودرجة التأكد، وملاحظة (رقم الصفحة مثلًا).
- البيانات الأولية عيّنة صغيرة (7 أشخاص من القائمة التي ذكرتها، أغنية واحدة، وحدثا الميلاد والوفاة بالسنتين اللتين ذكرتهما). عناصرها التجريبية تُحذف بزر واحد: **الإدارة ← نظرة عامة ← حذف البيانات التجريبية**.

## حقوق النشر

الموقع لا يتضمن أي مادة محمية. أضف فقط ما تملك حق استخدامه. حقل «الكلمات» اختياري ويُستخدم للبحث، فلا تضع فيه إلا ما تملك حق نشره. روابط الفيديو تُعرض عبر مشغل يوتيوب/فيميو الرسمي ولا تُنسخ.

## الأداء وسعة الأرشيف

- تحميل تدريجي للقوائم (24 عنصرًا ثم المزيد عند التمرير) بدل تحميل كل شيء.
- الصور: `loading="lazy"` مع مصغّرات تُنشأ عند الرفع.
- الصوت: `preload="none"`، فلا يُحمَّل أي ملف صوتي إلا عند الضغط على تشغيل، ويدعم التقديم والتأخير (Range).
- البحث: نص مفهرس مسبقًا ومُوحَّد عربيًا (يتجاهل التشكيل والهمزات والتاء المربوطة)، فيجد «قارئة الفنجان» و«قاريه الفنجان». مناسب لعشرات الآلاف من السجلات على SQLite.
- لتخزين ضخم أو حركة عالية: ضع الوسائط على CDN/تخزين سحابي واضبط `MEDIA_BASE_URL`، ويقبل حقل اسم الملف رابطًا كاملًا `https://...` أيضًا.

## المتغيرات

| المتغير | الغرض | الافتراضي |
|---|---|---|
| `DATA_DIR` | مجلد بياناتك (قاعدة + وسائط) | `./data` |
| `ADMIN_PASSWORD` | كلمة مرور الإدارة | تُولَّد وتُعرض مرة |
| `PORT` | المنفذ | 3000 |
| `MAX_UPLOAD_MB` | أقصى حجم للملف الواحد | 500 |
| `MEDIA_BASE_URL` | عنوان خارجي للوسائط (اختياري) | فارغ |
| `SESSION_SECRET` | مفتاح الجلسات (اختياري) | يُولَّد في `data/secret.key` |

## بنية البيانات

`songs` (العمل) ← `recordings` (كل نسخة: استوديو، حفلة، إذاعي، نادر...) وترتبط بـ `concerts` / `sessions` / `interviews` / `movies`. `people` مرتبطون بالأغاني كملحن وشاعر (`song_people`) وبالصور (`photo_people`). `media` لصوت وفيديو الحفلات والمقابلات. `sources` و`source_links` لأي كيان مع الحقل ودرجة التأكد. `timeline_events` أحداث يدوية، والباقي يُشتق من التواريخ. كل الجداول جاهزة لعشرات الآلاف من الصفوف.

## التطوير المستقبلي

- **الإنجليزية**: النصوص الثابتة في `public/js/*.js` والتسميات في `lib/schema.js` (كائن `LABELS`)؛ أعمدة `title_en`/`name_en` موجودة أصلًا في الأغاني والأشخاص والأفلام.
- **تغيير بنية القاعدة**: أضف عنصرًا جديدًا في مصفوفة `MIGRATIONS` داخل `lib/db.js` ولا تعدّل القديم.
- **الأمان**: خلف HTTPS، وكلمة مرور قوية. جلسة الإدارة كوكي `HttpOnly` و`SameSite=Strict`، وطلبات الكتابة محمية، ورفع الملفات مقيّد بالصيغ، ومحاولات الدخول محدودة.
- خطوط الموقع (Aref Ruqaa و IBM Plex Sans Arabic) تُحمَّل من Google Fonts. لاستضافتها ذاتيًا ضع ملفاتها في `public/fonts/` وأضف `@font-face`.
